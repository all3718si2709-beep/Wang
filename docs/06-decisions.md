# 06 決策記錄

已拍板的判斷與理由。要推翻請開 Issue 說明新資訊。

## D1 相機不碰尺寸
- **決定**:尺寸量測維持三次元 + 手工量具,相機只做外觀
- **理由**:三次元已達 0.001~0.005mm,遠高於需求;相機在 356mm 上做到卡尺精度需遠心鏡頭 + 恆溫,成本不合理且風險高
- **日期**:2026-09

## D2 外觀檢測用異常偵測,不用分類
- **決定**:模型學 OK 件,抓不像的
- **理由**:每批問題不一樣,無法事先收齊 NG 樣本;好件長一樣、壞件各異
- **日期**:2026-09

## D3 AI 不直接判 NG
- **決定**:AOI 輸出缺陷清單,規格引擎依允收標準下判定
- **理由**:代工要能對客戶解釋判定依據、可稽核;規則可追溯到版本
- **日期**:2026-09

## D4 獨立檢驗站,不做線上即時
- **決定**:零件放治具 → 拍 → 判 → 下一件
- **理由**:產量不定、各製程節拍不一,跟輸送帶綁死成本高且不必要
- **日期**:2026-09

## D5 先數位化再 AI
- **決定**:第 0 期只做規格引擎、量具整合、批次身分、報告產出;AOI 排第 2 期
- **理由**:AI 需要數據;先驗證再採購;第 0 期零技術風險且立即有回收
- **日期**:2026-09

## D6 小件先、大件後
- **決定**:AOI 先做 3~6 吋(單相機一張涵蓋),14 吋線掃 + 旋轉台留第 3 期
- **理由**:14 吋要 ~12,000 像素寬才能看 0.1mm,單相機做不到;小件先證明方法可行
- **日期**:2026-09

## D7 資料不上雲
- **決定**:照片、量測數據、客戶規格全留廠內
- **理由**:客戶規格與製程資料屬機密;AI 模型在本機訓練與推論可行
- **日期**:2026-09

## D8 先用手機拍照驗證,再買相機
- **決定**:第 1 期 AOI 離線驗證用現有零件 + 一般相機 + 固定打光
- **理由**:花時間不花錢;先知道抓得到多小、誤殺多少,再決定相機規格
- **日期**:2026-09

## D6 (修訂 2026-09-11) AOI 第一期直接做 6~10 吋,一開始就上旋轉台
- **原決定**:先做 3~6 吋單相機
- **修訂**:產量重心在 6~10 吋(152~254mm)。254mm 一張 20MP 只到 0.05mm/像素,0.2mm 以下鑄孔抓不穩;加上要檢內孔、全面,本來就要轉 → 第一期即配旋轉台,相機先用面陣分區拍,線掃看驗證結果再決定
- **3~6 吋與 14 吋**:同一套站體換配方涵蓋,不另分期

## D9 AOI 的價值定位:一致性 + 證據,不是速度
- **決定**:對廠內溝通時,AOI 不承諾快過人工 30 秒/件
- **理由**:旋轉 + 翻面 + 掃內孔的站,第一版幾乎不可能快過 30 秒。價值在:判定一致(不受疲勞)、每件留照片(客訴 / 退上游證據)、把人從「看」解放去做判斷處理
- **風險**:若廠內期待是「省一個人」,上線會失望。要先講開
- **日期**:2026-09-11

## D10 評估進料檢驗站
- **決定**:路線圖加入「毛胚進料檢驗」評估項
- **理由**:鑄孔退上游,但加工工時是自己的成本;一件 12~17 尺寸的加工做完才發現要退,機台時間白做。進料先擋表面鏽蝕、明顯鑄孔、外形變形,擋掉一成就省一成機台工時
- **限制**:多數鑄孔加工後才露出,進料檢只能擋一部分,不取代加工後檢驗
- **日期**:2026-09-11

## D11 批次身分從 ERP 取
- **決定**:不另造批次系統,以 ERP 的採購批號 / 工單號為批次主鍵
- **理由**:廠內已有 ERP;兩套身分會對不起來
- **待定**:ERP 品牌與接法(見 05 #1)
- **日期**:2026-09-11

## D12 不確定件進人工複判,不自動判死
- **決定**:AOI 信心度中間帶的件標「待複判」,由人決定
- **理由**:漏放與誤殺損失都可承受但須避免 → 不偏任一邊;人工複判量遠小於全檢,人力可負擔
- **日期**:2026-09-11

## D13 檢驗表依業界標準設計,外觀分類採 MSS SP-55
- **決定**:廠內無範本,不另創格式。外觀缺陷分類採 MSS SP-55(閥門鑄件目視標準)十二類 + 自訂「鏽蝕」「加工損傷」兩類;尺寸表採 PPAP / AS9102 通用版面
- **理由**:客戶多半本來就引用 SP-55,用它溝通沒有翻譯成本;退上游時分類也對得上鑄造廠的語言
- **日期**:2026-09-11
