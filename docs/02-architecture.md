# 02 系統架構:三層

「一個工具」拆成三層,各用對的方法。三層共用同一個資料底座(批次身分 + 檢驗紀錄)。

```
┌─────────────────────────────────────────────────────┐
│  第一層  規格引擎(規則,可解釋、可稽核)               │
│  客戶 → 料號 → 允收標準(外觀 × 區域 × 尺寸 × 數量;  │
│  尺寸項目 × 公差)→ 判定 OK/NG → 留紀錄 → 產報告      │
└──────────────▲──────────────────────▲───────────────┘
               │ 量測值                │ 缺陷清單(位置/大小/類型)
┌──────────────┴──────────┐  ┌────────┴────────────────┐
│ 第二層  尺寸整合(不 AI) │  │ 第三層  外觀 AOI(AI)    │
│ 三次元 CSV 自動匯入      │  │ 異常偵測:學 OK 件,      │
│ 手工量具藍牙化自動記錄    │  │ 抓不像的                 │
│ 精度 = 量具本身          │  │ 小件單相機 → 大件線掃     │
└─────────────────────────┘  └─────────────────────────┘
               │                       │
┌──────────────┴───────────────────────┴───────────────┐
│  資料底座:批次身分(供應商/爐號/日期)+ 每件檢驗紀錄   │
│  + 時間戳 + 環境(溫濕度)                              │
└──────────────────────────────────────────────────────┘
```

## 第一層 規格引擎

**它是什麼**:把品管的檢驗規範(SIP)數位化。不管數據從哪來,只負責判定、留紀錄、出報告。

**資料模型(草案)**
- 客戶
- 料號(屬於某客戶;直徑、面數、檢驗區域定義)
- 允收標準(屬於某料號、有版本)
  - 外觀:缺陷類型 × 區域 × 最大尺寸 × 最大數量
  - 尺寸:項目 × 標稱 × 上下公差 × 量具 × 抽檢頻率
- 批次(供應商、爐號、進料日期、數量)
- 檢驗紀錄(哪一件、哪一批、哪個站、時間、量測值/缺陷、判定、判定依據版本)

**為什麼是規則不是 AI**:判定要能對客戶解釋、要能稽核。AI 抓疑點,規則決定判不判 NG。

**產出**
- 每件 OK/NG + 理由
- 一鍵出批次檢驗報告 / COC
- 客訴時可回溯到件

## 第二層 尺寸整合

**原則:相機不碰尺寸。** 三次元已是 0.001~0.005mm 級,相機在 356mm 上做不到卡尺精度(需遠心鏡頭 + 恆溫,那個尺寸不合理)。

| 量具 | 用途 | 接法 |
|---|---|---|
| 三次元 | 首件、抽檢、全尺寸報告 | 軟體匯出 CSV → 小程式自動吃進系統 |
| 分厘卡 / 高度規 / 卡尺 | 巡檢、關鍵尺寸每件量 | 藍牙款或加藍牙傳輸模組(如 Mitutoyo U-WAVE) |

**AI 在這層只做趨勢**:
- 同料號連續幾件往公差邊緣飄 → 未超差先報(刀具磨耗 / 熱變形前兆)
- 累積後告訴你哪些尺寸從沒飄過(巡檢可省)、哪些常飄(每件量)→ 三次元時間花在真正有風險的地方

## 第三層 外觀 AOI

**方法:異常偵測(anomaly detection)**。餵大量 OK 件學「正常長什麼樣」,不像的抓出來。理由:好件長一樣、壞件每個壞法不同,而且每批問題不一樣,不可能事先收齊所有 NG 樣本。

**成敗 70% 在打光與相機架設,不在模型。** 金屬反光、鑄孔在特定角度才看得到。

**硬體分兩期**

| | 小件(3~6 吋) | 大件(至 14 吋) |
|---|---|---|
| 相機 | 20MP 面陣相機,一張涵蓋 | 線掃相機 + 旋轉台,轉一圈掃出展開帶 |
| 光源 | 均勻環光(鏽蝕)+ 低角度側光(鑄孔陰影) | 同上,配合線掃 |
| 全面檢測 | 翻面 / 多相機 | 外圓、內孔、端面各一道掃 |

**驗證先於採購**:先用現有零件 + 手機/相機 + 固定打光拍幾百張,本機離線驗證抓得到多小、誤殺率多少,再決定買什麼。照片全留本機。

**與第一層的介面**:AOI 輸出「缺陷清單(類型、位置區域、尺寸估計、信心度)」,由規格引擎依該料號允收標準判 OK/NG。AOI 不直接判 NG。

## 不做的事

- 不用相機量尺寸
- 不做跟輸送帶跑的線上即時檢測(節拍不一、產量不定,獨立站更合適)
- 不讓 AI 直接下判定(規則層下判定,AI 提供證據)
- 資料不上雲(照片、量測數據、客戶規格全留廠內)
